🛡️ SOLID Quick Reference

  • S - Single Responsibility: One reason to change. Separate business logic from logging/persistence.
  • O - Open / Closed: Open for extension, closed for modification. Use interfaces & polymorphism.
  • L - Liskov Substitution: Derived classes must be fully substitutable for base classes without breaking invariants.
  • I - Interface Segregation: Many client-specific interfaces are better than one general-purpose interface.
  • D - Dependency Inversion: Depend upon abstractions (pure virtual), not concrete details.

⚡ Smart Pointers & Ownership

  • std::unique_ptr<T>: Exclusive ownership. Zero runtime overhead. Move-only (no copy). Default choice for LLD.
  • std::shared_ptr<T>: Shared ownership via atomic control block reference counting. Use only when multiple owners truly exist.
  • std::weak_ptr<T>: Non-owning observer. Breaks cyclic dependencies between shared_ptr instances.

🔗 Class Relationships Cheat Sheet

  • Composition (──◆): "Has-a" with strict lifetime ownership. Child dies when parent dies (e.g. Car has Engine).
  • Aggregation (──◇): "Has-a" without lifetime ownership. Child outlives container (e.g. Department has Professor*).
  • Inheritance (──▷): "Is-a" relationship for polymorphism and interface realization.
  • Dependency (..>): "Uses-a" transient parameter or local variable in a method.

🔄 Concurrency Rules

  • Always use RAII wrappers: std::lock_guard<std::mutex> or std::unique_lock<std::mutex>. Never call mutex.lock() / unlock() manually.
  • Use std::scoped_lock (C++17) to acquire multiple mutexes simultaneously without deadlock risks.
  • Use std::shared_mutex for Read-Heavy workloads (multiple concurrent readers, exclusive single writer).
